## 2026-08-31 — 3D editor: three field bugs, one root cause each (71c260c)

Jorge's field report on the live editor: preview worked only sometimes, the
per-priority highlight did nothing, and the "Press START to resume" caption
did not come back when leaving the editor.

* **Intermittent preview**: the menu idle tick read a tab index snapshotted
  once at `menu3dsMenuSelectItem` entry, but L/R tab switches mutate
  `currentMenuTab` inside the loop — the snapshot went stale, so the tick
  thought the 3D tab was not focused. Worked only when something re-entered
  the function already on the tab (a dialog closing, the menu reopening).
  Fix: refresh the index every frame beside the idle callback.
* **Priority highlight did nothing**: the tile TEV
  (`TEX_ENV_REPLACE_TEXTURE0_COLOR_ALPHA`) takes RGB straight from
  TEXTURE0 — **vertex RGB never reaches the pixel** (for tiles the color
  attribute carries texcoords). The shader-side RGB dim was silently
  discarded. Dead end: modulating the TEV with PRIMARY_COLOR — impossible
  globally, because solid-color draws (backdrop/color math) feed their real
  color through the same attribute. Landed on the alpha route instead: the
  vertex alpha *is* modulated into the TEV, so zeroing it + the NE_ZERO
  alpha test can remove tiles per priority in-shader.
* **Caption not restored**: the caption texture only draws while the Paused
  notif is armed; the menu brackets its own pause render with
  trigger→sync→render→hide (`3dsmenu.cpp` ~1242). The preview's pausedLook
  now performs the same dance.

Validated in Azahar, SMW Yoshi's House: P0 vs P1 spotlights differ by ~31k
pixels; live gauge redraw; Y peek; caption restored on exit.

Workflow note (Jorge's idea): keep a **snes9x savestate** (slot 1) at the
test scene and load it after each rebuild — an Azahar-level savestate would
freeze the OLD emulator binary into RAM and resurrect it on load.

## 2026-08-31 — Sprites split into four priorities (0bad928, issue #60)

The rcmz feature gap. OBJ vertices already encode priority
(plane = (priority+1)*3, `S9xDrawOBJSHardware`), so the shader's two-tier
priority select grew into a four-tier cascade:

* `stereoIOD` keeps (tier0, tier1, boundary01); new `stereoIOD2` uniform
  (#8) carries (tier2, tier3, boundary12, boundary23).
* Selection is an overwrite cascade of three `ifc` blocks — picasso has no
  unconditional `jmp`, but `ifc cmp.x / … / .end` works.
* BG layers park the upper boundaries at `STEREO_TIER_PARKED` (99): only
  their two tile priorities ever match — bit-identical to before. The
  `gpu3dsSetStereoParallax(v)` wrapper parks them too, otherwise a stale
  OBJ boundary would leak into the window/depth prepass (window vertices
  carry high depth planes).
* Zero extra draw calls — the Old-3DS performance edge over rcmz's
  approach is untouched; cost is a few vertex-shader instructions.
* Model: sprite priorities 0/1 ride `Depth/DepthP1[4]` (the old single
  Sprites gauge drove both, so existing `.3d` files read the same);
  2/3 live in new `DepthOBJHi[2]`. `OBJ=` seeds all four; `OBJP2=`/`OBJP3=`
  override. Old builds ignore the new keys.
* BG3 "priority 1 front" ($2105 bit 3) needed no new slot: the draw macros
  already give that arrangement its own d1 plane, so the existing BG3
  Prio 1 gauge addresses it.

Validated in Azahar, SMW Yoshi's House — the spotlight separated the
chimney smoke (prio 0), Mario + berry block (prio 2) and the chimney flame
(prio 3); prio 1 empty in that scene, coherent.

## 2026-08-31 — Spotlight dims instead of hiding; live layer toggles

Jorge: the other priorities must stay VISIBLE (dimmed), not vanish; and the
Enable/Disable Layers diagnostics should repaint the paused frame live.

* **Two-pass spotlight** (preview only): the highlighted layer draws twice —
  first whole and dimmed like every other layer (atmosphere TexEnv forced to
  the "others" branch), then only the edited priority redrawn bright on top
  (other tiers alpha-hidden). Depth test is GEQUAL, so the equal-depth
  redraw wins; the OBJ layer draws with no depth test at all. Occlusion
  stays honest: a sibling-priority tile in front keeps covering the edited
  one, just dimmed.
* **Live toggles**: the replay in `gpu3dsDrawLayers` now skips layers with
  `LayerEnabled[id] == false` (in gameplay a disabled layer generates no
  vertices, so this changes nothing there), and the checkbox callback
  repaints the paused look immediately.

Validated in Azahar (SMW Yoshi's House) once the screen came back: BG1
P0/P1 spotlights show every other tile dimmed-but-visible (the berry block
sits dark inside the bright-P0 view instead of vanishing); Sprites Prio 2
lights only Mario + the berry block over a dimmed full scene; toggling BG1
off repaints the paused frame instantly (tree gone, caption kept) and back
on restores it. 144 host tests green.

## 2026-08-31 — Dialogs sized to their text (Jorge's report)

Two clipping/dead-space bugs, one root cause: dialogs guessed their height
instead of measuring their text.

* **Picker descriptions clipped** (Slider Response, Edge Cleanup): the
  fixed 76px header fits 3 lines; those descriptions render 5. First
  attempt counted explicit `\n` only — still clipped, because lines also
  wrap BY WIDTH. Fix: extracted the wrap scanner out of
  `ui3dsDrawStringWithWrapping` into `ui3dsScanWrappedLines` (one logic,
  two callers - no new copy-paste pair, see issue #41's lesson) and the
  dialog header now counts with the exact same algorithm the draw uses.
  Dialogs of up to 3 lines stay pixel-identical. The two descriptions
  also lost their manual `\n`s — natural wrapping breaks cleaner.
* **"Loading Game:" dead space**: 112px fixed height with ~45px of
  content when no thumbnail exists. Now content-sized (title + wrapped
  name lines + padding); the thumbnail path is untouched.

Validated in Azahar: Slider Response shows all 5 lines with clean breaks;
the loading dialog hugs its two lines of text.
